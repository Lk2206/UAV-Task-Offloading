# Optimal UAV Task Offloading in Edge–Cloud Computing

> **Design and Analysis of Algorithms (DAA) Course Project**  
> A mathematically grounded simulation, optimization, and comparison suite evaluating computational offloading decisions for Unmanned Aerial Vehicles (UAVs) across Edge and Cloud computing tiers.

---

## 1. Project Overview & Motivation

Unmanned Aerial Vehicles (UAVs or drones) play an essential role in disaster surveillance, search-and-rescue, environmental mapping, and real-time object tracking. However, UAVs have strict onboard hardware constraints:
- **Limited Battery Capacity**: High-performance processors drain battery life exponentially, reducing flight duration.
- **Constrained Computational Power**: Complex computer vision and image processing algorithms demand billions of CPU cycles that exceed low-power drone hardware.
- **Strict Quality-of-Service (QoS) Deadlines**: Mission-critical tasks (such as obstacle detection) must complete within milliseconds to prevent mission failure.

**Core Objective**:  
Build an academically rigorous simulation system that decides where computational tasks generated by UAVs should execute:
1. **Locally on the originating UAV** (zero transmission delay, constrained compute capacity, high battery drain).
2. **On an Edge Server** (low network latency, medium compute capacity, finite task slots).
3. **On a Central Cloud Server** (high compute capacity, infinite virtual scaling, but higher network transmission and backbone latency).

The objective is to **minimize total completion delay** and deadline violations while strictly respecting computing capacity limits, server task slots, and communication bottlenecks.

## 3. Mathematical Model & Cost Calculations

To ensure scientific correctness, all physical quantities and units are strictly standardized:

| Parameter | Unit | Description |
| :--- | :--- | :--- |
| **Task Size** ($S_i$) | Megabytes (MB) | Data volume that must be transmitted over the radio link. |
| **CPU Work** ($W_i$) | Gigacycles ($\text{GC} = 10^9$ cycles) | Computational effort required to complete the task. |
| **Computing Capacity** ($F_j$) | Gigacycles per second ($\text{GC/s}$) | Processing speed / compute rate of the execution location. |
| **Bandwidth** ($B_{u,j}$) | Megabits per second (Mbps) | Available channel transmission throughput. |
| **Network Latency** ($\tau_{u,j}$) | Seconds (s) | Shortest routing latency computed via Dijkstra's algorithm. |
| **Task Deadline** ($D_i$) | Seconds (s) | Maximum allowable turnaround time before QoS violation. |

### 3.1 Transmission Delay
$$\text{Time}_{\text{trans}}(i, j) = \frac{S_i \times 8}{B_{u,j}} \quad [\text{seconds}]$$
*(For local UAV execution, $\text{Time}_{\text{trans}} = 0$)*.

### 3.2 Processing Delay
$$\text{Time}_{\text{proc}}(i, j) = \frac{W_i}{F_j} \quad [\text{seconds}]$$

### 3.3 Total Response Time
$$\text{Delay}_{\text{total}}(i, j) = \text{Time}_{\text{trans}}(i, j) + \tau_{u,j} + \text{Time}_{\text{proc}}(i, j)$$

### 3.4 UAV Energy Consumption
- **Local execution**: $E_i = P_{\text{cpu}} \times \text{Time}_{\text{proc}}$ (where $P_{\text{cpu}} = 2.0\text{ W}$).
- **Offloaded execution**: $E_i = P_{\text{tx}} \times \text{Time}_{\text{trans}} + P_{\text{idle}} \times (\tau + \text{Time}_{\text{proc}})$ ($P_{\text{tx}} = 1.2\text{ W}, P_{\text{idle}} = 0.2\text{ W}$).

## 4. Algorithms Implemented & Complexity Analysis

| Algorithm | DAA Paradigm | Time Complexity | Space Complexity | Optimality Guarantee |
| :--- | :--- | :--- | :--- | :--- |
| **Dijkstra Routing** | Greedy (Min-Heap Priority Queue) | $\mathcal{O}((V + E) \log V)$ | $\mathcal{O}(V + E)$ | Globally optimal network latency paths |
| **Greedy Offloading** | Greedy Heuristic | $\mathcal{O}(N \cdot (E + C))$ | $\mathcal{O}(N + U + E + C)$ | Local optimum only; no global guarantee |
| **Dynamic Programming** | Multidimensional Knapsack (MMKP) | $\mathcal{O}(N \cdot W_E \cdot W_C \cdot \prod W_U)$ | $\mathcal{O}(N \cdot W_E \cdot W_C)$ | Mathematically optimal for stated discrete model |
| **EDF Scheduling** | Priority Queue / Timsort | $\mathcal{O}(N \log N) + \mathcal{O}(N \cdot \text{Loc})$ | $\mathcal{O}(N)$ | Earliest deadline timeline heuristic |
| **Priority Scheduling** | Criticality Tiering | $\mathcal{O}(N \log N) + \mathcal{O}(N \cdot \text{Loc})$ | $\mathcal{O}(N)$ | High-criticality preservation |
| **Combined Scheduling** | Multi-attribute Tiering | $\mathcal{O}(N \log N) + \mathcal{O}(N \cdot \text{Loc})$ | $\mathcal{O}(N)$ | Balanced criticality and deadline QoS |

### 4.1 Dynamic Programming Formulation (MMKP)
The offloading decision is formulated as a **Multiple-Choice Multidimensional Knapsack Problem**:
- Let $N$ tasks be indexed $i \in \{1, \dots, N\}$.
- Let discrete CPU capacities be $W_E = \lfloor C_E / \Delta \rfloor$, $W_C = \lfloor C_C / \Delta \rfloor$, and $W_{u} = \lfloor C_{u} / \Delta \rfloor$ with quantum $\Delta$ (default 1.0 GC).
- **State Representation**: $(i, e, c, \mathbf{u})$, where $i$ is the task stage, $e$ is Edge CPU consumed, $c$ is Cloud CPU consumed, and $\mathbf{u} = (u_1, \dots, u_K)$ is the vector of UAV local capacities.
- **Bellman Recurrence**:
  $$\text{DP}[i, e, c, \mathbf{u}] = \min_{d \in \mathcal{D}_i} \Big\{ \text{DP}[i-1, e - r_{i,e}, c - r_{i,c}, \mathbf{u} - \mathbf{r}_{i,u}] + \text{Cost}(i, d) \Big\}$$
  where $\text{Cost}(i, d)$ is $\text{Delay}(i, d)$ for feasible allocations or penalty $P = 1000\text{s}$ for unallocated tasks.
- **Reconstruction**: Every transition stores backpointers to trace back the exact optimal assignment vector without heuristics.
- **Instance Bound**: To guard against exponential memory explosion, DP is bounded to instances where $N \le 25$ and total reachable states $\le 150,000$.

## 8. Limitations & Future Scope

### Limitations
1. **Discretization Trade-off**: The exact DP discretizes CPU cycles using a finite step size ($\Delta$). Smaller step sizes yield higher precision at the cost of larger state-space tables.
2. **Deterministic Mobility**: The current model evaluates stationary UAV communication hops during the offloading window; dynamic kinematic 3D trajectory tracking is left as future work.
3. **Queue Independence**: Independent single-core FIFO queues are modeled per node; multi-core thread preemption is simulated at the server level.

### Future Scope
- Integration of Reinforcement Learning (Deep Q-Networks / PPO) for time-varying multi-agent UAV swarms.
- Doppler effect and Rayleigh fading RF wireless channel modeling.
- Real-time flight trajectory battery drainage coupling.
